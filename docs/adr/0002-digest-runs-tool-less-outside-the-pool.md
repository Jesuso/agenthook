# The digest agent runs tool-less, outside the slot pool

The Digest is generated by a `claude -p` the receiver spawns on request. We run it with every tool
disabled, feeding it a payload the receiver builds (tickets, PRs, events, cost, the SOUL), and keep it
outside `maxConcurrent` with one in flight per profile.

## Why

- A digest matters most when the profile is busy, so it cannot wait behind ticket agents for a slot.
- Read-only by construction beats read-only by flag: a tool-less agent cannot touch the board, the
  repo or files, whatever `fullAuto` says, and the UI process still spawns nothing.
- The cost is depth: it only knows what the payload holds. `digest.access` is reserved for widening
  that later (read-only MCP, repo in plan mode) as an explicit per-profile opt-in.

## Consequences

- A new receiver op (`digest`) and a new state file (`digest.json`), both receiver-written.
- Digest cost is reported on the digest, not in ticket cost or "cost today".
