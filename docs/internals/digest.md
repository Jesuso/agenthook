# Digest and ticket summaries

## Key files

- `src/digest.js` + `src/digest-config.js` — the on-demand **Digest** (docs/web-ui.md, ADR 0002): `buildSnapshot` (pure over a state dir), `buildDigestArgs` (tool-less `claude -p`, project settings only, never `fullAuto`), `createDigester` (single-flight per language, outside the slot pool, emits `digest_start`/`digest_end`). Per language: `request({lang})` writes in `lang` → `cfg.language` → `en`, and `<stateDir>/digest.json` is `{ byLang: { <lang>: DigestView } }` (`readDigest(dir, lang)` / `writeDigest`; a legacy flat record reads as the `en` entry and is kept under `language`/`en` on the next write). Model `digest.model` → `summaries.model` → `claude-haiku-5-5`; budget `digest.maxBudgetUsd` → `summaries.maxBudgetUsd`. `buildToolLessArgs` (alias `buildDigestArgs`) and `runClaudeJson` are shared with the summarizer. Reached only through the `digest` control op (`ops.js`, optional `lang`) ← `POST /api/digest` (`GET /api/digest?lang=` reads that entry); the SOUL file (`digest.soul`, default `SOUL.md` beside the config) is on the instructions allowlist with scope `soul`.
  `buildDigestPrompt` also asks the agent to write a listen-friendly version in the same run: a line
  containing exactly `SPOKEN_MARKER` (`"=== SPOKEN ==="`) after the markdown digest, then 2-4 plain
  sentences with no ticket ids, code identifiers or markdown. `splitSpoken(result)` (pure) splits on
  the **last** such line; no marker, an empty part before it, or an empty spoken part after it all
  fall back to the whole result as `text`. `createDigester`'s `generate` stores the spoken part as
  `rec.spoken` (capped at 600 chars), omitted when absent. `DigestView.spoken` (`src/ui/contract.js`)
  is optional so older records still read; the UI's read-aloud 🔊 speaks `digest.spoken || digest.text`.
- `src/ticket-summary.js` — `summarizeDescription` (pure): a tracker description → one plain paragraph (≤240 chars, first prose paragraph, markdown/fences/checklists stripped), stored by dispatch as `refmeta.summary` and shown by the UI as what a ticket is about (instantly; the table tooltip keeps it).
- `src/summarize.js` — the drawer's **localized ticket summary**: `buildSummaryPrompt` (pure; the description between nonce'd DATA fences, plain text ≤240 chars in `lang`), `summarize` (one tool-less run, `summaries.model` default `claude-haiku-5-5`, `summaries.maxBudgetUsd` default 0.1, throwaway cwd, markdown stripped + hard clip), `createSummarizer` → `request({ref, lang})`. Fail-closed: a ref missing from refmeta is refused before any tracker read; then `fetchTask` (the current description — refmeta has none) and refuse an epic or a ticket not assigned to us (unless `assigneeFilter: false`). Cache `<stateDir>/ticket-summaries.json` = `{ <ref>: { <lang>: {hash, text, generatedAt, costUsd?} } }` (`hash` = short sha256 of the description; a different hash is a miss that replaces the entry and prunes the ref's other stale languages; untracked refs are dropped on write). In-flight join per (ref, lang, hash), at most 2 runs at once on a local semaphore (never the queue), `summary_end` on runs only. An empty description returns `text: null` with no run. Reached only through the `summary` control op (`ops.js`; not a `write` — no board-cache reset, no audit; `lang` must be BCP-47, canonicalized by `digest-config.js` `canonicalLang`) ← `POST /api/summary` (guarded like the digest; the UI's `ticketSummary.ts`). Not an MCP tool; never on boot or a timer.
